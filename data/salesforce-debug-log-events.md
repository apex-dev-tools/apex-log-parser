# Salesforce Debug Log Events Reference

**Source:** [Working with Logs in the Developer Console](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_debugging_system_log_console.htm)
**Date Extracted:** 2026-04-14
**Total Events:** 185 (official), 299 (including unofficial)

## Log Structure

- **Max size:** 20 MB
- **Truncation chunk:** 200 KB removed when max size reached
- **Retention:** System logs 24h, Monitoring logs 7 days
- **Generation limit:** 1000 MB per 15 min window
- **Header format:** `{api_version} {CATEGORY,LEVEL;...}`
- **Timestamp:** `HH:mm:ss.SSS (nanoseconds_elapsed)`
- **Field delimiter:** `|`
- **Session IDs:** Replaced with `SESSION_ID_REMOVED`
- **Managed package/built-in code:** `[EXTERNAL]`

**Not included in debug logs:** Time-based workflow actions, Lead conversion triggers, Standard/custom Visualforce email template controllers

## Debug Log Categories

| Category | Default Level | Description |
|---|---|---|
| **Apex Code** | DEBUG | Apex execution: methods, triggers, exceptions, debug statements |
| **Apex Profiling** | INFO | Governor limits, cumulative profiling, stack frames |
| **Callout** | INFO | External web service request/response details |
| **Data Access** | — | Data access policy rule evaluations and object access control |
| **Database** | INFO | Database activity: DML, SOQL, SOSL, savepoints |
| **NBA** | — | Einstein Next Best Action strategy/node execution |
| **System** | DEBUG | System method calls, mode transitions, duplicate detection |
| **Validation** | INFO | Validation rule evaluations (pass/fail/error) |
| **Visualforce** | INFO | VF page serialization, formula evaluation, apex calls |
| **Wave** | — | Analytics (CRM Analytics) app lifecycle, templates, diffs |
| **Workflow** | INFO | Workflow rules, flows, processes, approval actions |

Default levels apply when no trace flags are active (e.g. during Apex tests).

## Debug Log Levels

Log levels (from lowest to highest): NONE < ERROR < WARN < INFO < DEBUG < FINE < FINER < FINEST

The level is cumulative. Selecting FINE includes all events at DEBUG, INFO, WARN, and ERROR levels.

## Truncation Policy

When a log exceeds 20 MB, 200 KB chunks are removed, usually starting with older lines. Lines can be removed from any location.

The following 15 events are **never removed** during truncation:

- `CALLOUT_REQUEST`
- `CALLOUT_RESPONSE`
- `CODE_UNIT_FINISHED`
- `CODE_UNIT_STARTED`
- `CONSTRUCTOR_ENTRY`
- `CONSTRUCTOR_EXIT`
- `EXECUTION_FINISHED`
- `EXECUTION_STARTED`
- `FATAL_ERROR`
- `METHOD_ENTRY`
- `METHOD_EXIT`
- `SOQL_EXECUTE_BEGIN`
- `SOQL_EXECUTE_END`
- `SOSL_EXECUTE_BEGIN`
- `SOSL_EXECUTE_END`

Content *between* protected start/end pairs may still be removed.

## Code Unit Types

Types of work delimited by CODE_UNIT_STARTED/CODE_UNIT_FINISHED. A class is not a discrete unit of code.

- Triggers
- Workflow invocations and time-based workflow
- Validation rules
- Approval processes
- Apex lead convert
- @future method invocations
- Web service invocations
- executeAnonymous calls
- Visualforce property accesses on Apex controllers
- Visualforce actions on Apex controllers
- Batch Apex start, finish, and execute methods
- Scheduled Apex System.Schedule execute method
- Incoming email handling
