'@apexdevtools/apex-log-parser': major
---

The new parser is now the default, at the package root. The old parser is removed.

**5–8× faster and 6× less memory used vs v0.3**, on logs of 8 to 100 MB. A 100 MB log parse was measured at 182 ms instead of 1,215 ms, with 141 MB memory held instead of 812 MB. Against v0.2.0 it is 6–9× faster, with 8× less memory.

- `parse` is async. It reads a string, bytes, a `Blob`, a `fetch` `Response`, a `ReadableStream` or an async iterable. It works in time slices of 5 ms. `signal` stops it, and `onProgress` reports how far it is.
- Optional: the `worker` option runs the parse in a worker loaded from `@apexdevtools/apex-log-parser/worker`. In a browser, use a `blob:` URL for the worker.
- Optional: `toBuffers` and `fromBuffers` move a parsed log to another thread without a copy.
- Each event has a `kind` and `details`. `ofType` finds every event of the types you name. `columns` gives the times and tree links of every event as plain arrays.
- A const for each public union, and `DEBUG_CATEGORY_TOKEN`, the log header token of each debug category.
- A Node build and a browser build are both available.

**Breaking changes, from v0.3's default parser:**

- `parse(text)` returns a `Promise<ApexLog>`: `await parse(text)`.
- The event classes, the `ApexLog` class and `ApexLogParser` are removed. `ApexLog` is now a type. Instead of `instanceof SOQLExecuteBeginLine`, test `event.type === 'SOQL_EXECUTE_BEGIN'`, or `event.kind === 'soql'` for every SOQL event. `ofType('SOQL_EXECUTE_BEGIN')` types `details`.
- `LogEvent` is now `ApexEvent`: a `FrameEvent` or a `LeafEvent`. `isParent` is now `isFrame`. A leaf's `children` is always empty.
- `ApexLog` is not an event: it has no `type`, `text` or `parent`. A top-level event has `parent: null`.
- `eventIndex` is now `id`. Ids start at 1 and are valid within one parse only. Use `log.event(id)` in place of `eventsById[i]`, and `log.events` for every event.
- An exit line, such as `METHOD_EXIT`, is no longer an event. It sets `exitStamp` and `duration` on its frame. A merged package entry is no longer an event.
- `logIssues` is now `issues`, and `governorLimits` is now `limits`. On an issue and a truncation region, `eventIndex` is now `event`.
- A value the log does not state is `null`, not `''`, `0`, `'default'`, the type name or absent. This covers `text`, `namespace`, `category`, `cpuType`, `lineNumber` and a limit's `limit`.
- The parser state on each event is removed: `logParser`, `isExit`, `acceptsText`, `nextLineIsExit` and `discontinuity`. Use `eventType(event.type).exitTypes` for `exitTypes`.
- `limitUsage` is now `details`.
- `suffix` is removed. It was display text, such as ` (code unit)` or ` (Flow)`. A caller that wants a label builds it from `type` and `text`. For what started a flow, read `details.codeUnitType` of the code unit above it.
- `executionEndTime` is removed. `exitStamp` is where the log ends. For the end of the last frame at the top, read the `exitStamp` of the last frame in `children`.
- The limit, user and debug level types are readonly. On an event from `ofType`, `field(name)` takes only the names its type lists.
- Renames: `LOG_LEVEL` → `LEVEL`, `LOG_CATEGORY` → `CATEGORY`, `LogEventType` → `EventType`, `LogCategory` → `Category`, `LogLevel` → `Level`, `CPUType` → `CpuType`, `GovernorSnapshot` → `LimitSnapshot`, `Truncation` → `LogTruncation`, `TruncationRegion` → `LogTruncationRegion`, `LimitMetricKey` → `LimitMetric`, `LimitObservation` → `LimitUsage`, `RunningTotalObservation` → `RunningUsage`.
- Removed: `ALL_LOG_CATEGORIES` (use `Object.values(CATEGORY)`), `LIMIT_METRIC`, `ALL_LIMIT_METRICS`, `LimitMetricUnit`, `LimitMetricMeta`, `DebugLevels` and `LineNumber`.
- The `./next` and `./next/worker` paths are removed: import from the package root, and start the worker from `./worker`.
