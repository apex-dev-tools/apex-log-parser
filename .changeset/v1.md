'@apexdevtools/apex-log-parser': major
---

The new parser is now the default, at the package root. In v0.3 it was experimental, at `@apexdevtools/apex-log-parser/next`. The old parser is removed.

**5–8× faster and 6× less memory used vs v0.3**, on logs of 8 to 100 MB. A 100 MB log parse was measured at 182 ms instead of 1,215 ms, with 141 MB memory held instead of 812 MB. Against v0.2.0 it is 6–9× faster, with 8× less memory.

- `parse` is async. It reads a string, bytes, a `Blob`, a `fetch` `Response`, a `ReadableStream` or an async iterable.
- It works in time slices of 5 ms, so the page or the event loop stays responsive. `signal` stops it, and `onProgress` reports how far it is.
- Optional: for more speed and a clear main thread, the `worker` option runs the parse in a worker that loads `@apexdevtools/apex-log-parser/worker`. In a browser, use a `blob:` URL for the worker.
- Optional: `toBuffers` and `fromBuffers` move a parsed log to another thread without a copy.
- Each event tells you what kind of work it is (`kind`), and gives the extra values on its log line (`details`). `ofType` finds every event of the types you name. `columns` gives the times and tree links of every event as plain arrays.
- A Node build and a browser build are both available.

**Breaking changes, from v0.3's default parser:**

- `parse(text)` returns a `Promise<ApexLog>`: `await parse(text)`.
- The event classes, the `ApexLog` class and `ApexLogParser` are removed, so `instanceof` no longer works on them. `ApexLog` is now a type. Instead of `instanceof SOQLExecuteBeginLine`, test `event.type === 'SOQL_EXECUTE_BEGIN'`, or `event.kind === 'soql'` for every SOQL event. `ofType('SOQL_EXECUTE_BEGIN')` gives them all, with their `details` typed.
- `LogEvent` is now `ApexEvent`: a `FrameEvent` or a `LeafEvent`. A leaf's `children` is always empty. `isParent` is now `isFrame`.
- `ApexLog` is not an event. It has the rollups, `children` and `exitStamp`, but no `type`, `text` or `parent`. An event at the top of the log has `parent: null`.
- `eventIndex` is now `id`. Ids start at 1, and are valid within one parse only. They are renumbered: exit lines and merged package entries get no id, so an old index does not name the same event. Use `log.event(id)` in place of `eventsById[i]`, and `log.events` for every event in id order. `event(id)` gives the same object on every call.
- An exit line, such as `METHOD_EXIT`, is no longer an event. It sets its frame's `exitStamp` and `duration`.
- `logIssues` is now `issues`, and `governorLimits` is now `limits`. On an issue and a truncation region, `eventIndex` is now `event`, and a field the log does not state is `null`, not absent.
- A value the log does not state is `null`: `text` instead of the type name, `namespace` instead of `'default'`, `category` and `cpuType` instead of `''`, and `lineNumber` instead of `0`. `debugCategory` and `debugLevel` are always stated, so they are never `''`.
- The parser state on each event is removed: `logParser`, `isExit`, `acceptsText`, `nextLineIsExit` and `discontinuity`. `exitTypes` is now `eventType(event.type).exitTypes`.
- A limit line's reading is in `details`, not `limitUsage`.
- `LOG_LEVEL` is now `LEVEL`, and `LOG_CATEGORY` is now `CATEGORY`. `ALL_LOG_CATEGORIES` is removed: use `Object.values(CATEGORY)`. `LIMIT_METRIC`, `ALL_LIMIT_METRICS` and the `LimitMetricUnit` and `LimitMetricMeta` types are removed.
- Type renames: `LogEventType` → `EventType`, `LogCategory` → `Category`, `LogLevel` → `Level`, `CPUType` → `CpuType`, `GovernorSnapshot` → `LimitSnapshot`, `Truncation` → `LogTruncation`, `TruncationRegion` → `LogTruncationRegion`, `LimitMetricKey` → `LimitMetric`, `LimitObservation` → `LimitUsage` and `RunningTotalObservation` → `RunningUsage`. `DebugLevels` and `LineNumber` are removed.
- The `./next` and `./next/worker` paths are removed: import from the package root, and start the worker from `./worker`.
